# ユーザーによる魚種登録 + 管理者へのメール通知 セットアップ

## 全体の流れ

1. ユーザーが「釣果を記録する」の魚種検索で見つからない魚を **図鑑に登録** する
2. `fish` テーブルに INSERT される。DBトリガーにより
   - ID は `u001`, `u002`… を自動採番
   - `needs_review = true`（要整備）、画像なし（仮画像 `public/fish-placeholder.svg` を表示）
   - レア度は「定番」(2)、シリーズ・解説欄は空
   - 同名の魚が既にある場合と、1人24時間で5件を超える場合は登録を拒否
3. Database Webhook → Edge Function `notify-new-fish` → Resend 経由で管理者にメールが届く
4. 管理者は「管理 → 魚種の管理」を開く（要整備があれば最初から「要整備のみ表示」）
   - 画像・英名・レア度・解説などを整備して保存すると「要整備」が外れる
   - 必要なら表示順やシリーズもここで調整する

## セットアップ手順（一度だけ）

### 1. SQL を実行

Supabase dashboard → SQL Editor で `supabase/user_fish_schema.sql` を実行。

### 2. Resend の準備

1. https://resend.com に **通知を受け取りたいメールアドレス** でサインアップ（無料枠: 3,000通/月）
2. API Keys → Create API Key（Sending access で可）
3. 独自ドメインを使わない場合、送信元は `onboarding@resend.dev` になり、
   **Resend アカウントのメールアドレス宛てにしか送れない**。通知先は自分だけなので問題ない。

### 3. Edge Function をデプロイ

```bash
npx supabase login
npx supabase link --project-ref <your-project-ref>

npx supabase secrets set \
  RESEND_API_KEY=re_xxxxxxxx \
  NOTIFY_EMAIL=<通知先メールアドレス> \
  WEBHOOK_SECRET=<適当な長いランダム文字列>

# Webhook からは独自ヘッダで認証するので JWT 検証はオフ
npx supabase functions deploy notify-new-fish --no-verify-jwt
```

### 4. Database Webhook を作成

Supabase dashboard → Database → Webhooks → Create a new hook

| 項目 | 値 |
| --- | --- |
| Name | `notify_new_fish` |
| Table | `public.fish` |
| Events | `Insert` のみ |
| Type | Supabase Edge Functions |
| Edge Function | `notify-new-fish`（POST） |
| HTTP Headers | `x-webhook-secret: <手順3の WEBHOOK_SECRET>` |

### 5. 動作確認

一般ユーザー（管理者でないアカウント）でログインし、図鑑にない名前で魚を登録 → メールが届けばOK。
届かない場合は dashboard → Edge Functions → notify-new-fish → Logs を確認。

※ 管理者が管理画面から追加した魚種は `needs_review = false` なので通知されない。
