## 1. サイズクラス分け（ベビー / ひよっこ / おとな / ヌシ）

### ロジック
`FISH_DB` の各魚は `size:[min,max]` を持っている（例: マアジ `[15,35]`）。
この範囲を **均等に4分割** し、記録時に入力されたサイズ(cm)がどの区分に入るかを判定する。

```js
function classifyBySize(fish, sizeCm){
  if(sizeCm == null || sizeCm === '') return null;
  const [min, max] = fish.size;
  const range = max - min;
  const q1 = min + range * 0.25;
  const q2 = min + range * 0.50;
  const q3 = min + range * 0.75;
  const size = Number(sizeCm);
  if(size < q1) return 'baby';
  if(size < q2) return 'kid';
  if(size < q3) return 'adult';
  return 'nushi'; // 規格外の大物
}

const SIZE_CLASS_INFO = {
  baby:  { label: 'ベビー',   color: '#8fd3f4', emoji: '🐣' },
  kid:   { label: 'ひよっこ', color: '#3ba7e0', emoji: '🐥' },
  adult: { label: 'おとな',   color: '#29c48f', emoji: '🐟' },
  nushi: { label: 'ヌシ',     color: '#e0b13b', emoji: '👑' },
};
```

- min未満やmax超過の実測値もあり得るので、`size < q1` を下限、`size >= q3` を上限として扱えばクランプ不要（自然に吸収される）。
- サイズ未入力の場合はクラス判定なし（`null`）。UI上は「クラス不明」扱いで表示。

### UI反映箇所
- **記録保存時**：`record` オブジェクトに `sizeClass` を追加して保存。
- **ログ一覧**：各記録にクラスバッジ（絵文字＋ラベル、色は `SIZE_CLASS_INFO` の color）を表示。
- **図鑑詳細モーダル**：捕獲済みの場合、記録ごとにクラスを表示。
- **Gotcha演出**：初捕獲時、判定されたクラスに応じて演出の色味・エフェクトの強さを変える（下記4.のレア演出と連動）。

### 拡張案（任意・後回しでOK）
種×クラスの組み合わせ（71種×4クラス）をコンプリート対象にする「クラス別図鑑」。これは図鑑のやり込み要素が一気に増えるので、基本実装が終わってから相談する。まずは記録・表示のみでよい。

## 2. 魚のキャラクター化（AI生成イラスト）

### 方針
現状の絵文字（🐟🐡🦈🦑）表示を、種ごとのAI生成キャラクターイラストに置き換える。

### 進め方（2段階）
**Phase 1: アートスタイル確定（5〜10種でサンプル生成）**
- 対象：レアリティ・カテゴリ（海水/淡水）・見た目の異なる魚を意図的に選ぶ
  - 例）マアジ(rarity1,銀)、キジハタ(rarity3,赤)、クエ(rarity5,伝説級)、イトウ(rarity5,淡水伝説)、アオリイカ(rarity3,軟体)、トラフグ(rarity4,毒魚)
- スタイル候補（相談の上どれか1つに決定）：
  - ゆるキャラ・マスコット風（丸みのある可愛いデフォルメ）
  - 図鑑チックなセミリアル（生態がわかる系統）
  - ドット絵・ピクセルアート（レトロゲーム感）
- 各魚の性格・特徴（下記3.）をイラストの表情・ポーズに反映させる
- 透過PNG、正方形（1024×1024推奨、カモの小屋ロゴと同じ仕様）

**Phase 2: 残り種の量産**
- Phase1で確定したスタイルガイド（プロンプトテンプレート）を使い、残り約60種を生成
- レアリティが高い魚（rarity4-5）は特別感を出す演出を追加（後光・エフェクトなど）

### データ構造変更
```js
// FISH_DB の各要素に追加
{
  id:1, name:"マアジ", ...,
  emoji:"🐟",              // フォールバック用に残す
  illustration: "assets/fish/001_maaji.png", // 追加
}
```
- 画像が見つからない/未生成の種は既存の絵文字表示にフォールバックする（`onerror`でemoji表示に切り替え）。

### クラス別の見た目差
個別イラストをクラスごとに4パターン作るのはコスト高（71種×4=284枚）なので、**1種につき1枚のベースイラスト**とし、クラスの違いは以下で表現する：
- サイズ感（CSSで表示サイズを変える：ベビーは小さく、ヌシは大きく＋枠を金色に）
- バッジ（1.の`SIZE_CLASS_INFO`のエンブレムを画像に重ねる）

## 3. 魚のキャラクター設定（性格・口癖・豆知識）

既存の `habitat` フィールド（豆知識）に加え、キャラクター性を持たせる。

```js
{
  id:1, name:"マアジ", ...,
  habitat:"堤防・防波堤の定番。回遊してくる。", // 既存：豆知識
  personality: "人懐っこくて社交的。群れでいるのが好き。", // 追加：性格
  catchphrase: "みんなで泳ぐの、楽しいアジ！", // 追加：口癖・セリフ
}
```

- `personality` と `catchphrase` は71種すべてに作成が必要（データ入力作業）。まずは人間が種の特徴から性格を考え、Claude APIまたは手動で一括生成する方式を提案。
- 図鑑詳細モーダルに「せいかく」「ひとこと」欄を追加表示。
- Gotcha演出（初捕獲時）で `catchphrase` を吹き出し風に表示すると盛り上がる。

## 4. わくわく要素（前回合意分）

以下、優先度高い順に実装。

1. **称号・ランク**：図鑑コンプ率に応じて「見習い→ベテラン→伝説の釣り師」等の称号をヘッダーやプロフィールに表示
2. **レアリティ別Gotcha演出**：rarityが高いほど演出を派手に（エフェクト・色・サウンド的な間の取り方）
3. **自己記録更新演出**：同じ種で過去最大サイズを更新したら「自己ベスト更新！」バナー表示
4. **季節・時間帯限定の魚**：`pickCandidate` の出現ロジックに、現在の月・時間帯でフィルタ/重み付けを追加（例：アユは初夏に出やすい等）
5. **地図表示で釣行スポット記録**：記録時に位置情報（手動入力の地名 or 端末位置情報）を保存し、簡易マップ表示
6. **友達・accoさんとの図鑑シェア対戦**：現状GASバックエンドがないため、他プロジェクト同様「GAS + Google Sheets」構成に乗せるかは別途相談（今はローカルstateのみ）

## 実装順序の提案

1. サイズクラス分けロジック＋UI反映（コストゼロ、すぐできる）
2. キャラクター性格・口癖データの作成（テキストのみ、イラスト待たずに先行可能）
3. わくわく要素の1〜3（称号・レア演出・自己ベスト更新）
4. イラスト Phase1（サンプル生成→スタイル確定）
5. イラスト Phase2（量産）
6. 季節限定・地図・シェア対戦（バックエンドが絡むので最後）

## 補足
- 現状 `tsurizukan.html` は単一ファイルのプロトタイプ（バックエンドなし、localStorageも未使用）。地図・シェア機能はGAS連携が前提になるため、他プロジェクト（カモの小屋アプリ等）と同じアーキテクチャパターン（GAS + Google Sheets）に乗せるか検討が必要。
